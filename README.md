# Лимит скорости

Небольшое приложение для Windows на Rust: ограничивает **скорость загрузки** (входящий трафик) для выбранных программ. Интерфейс на egui в стиле Material 3, тёмная и светлая темы.

## Как это работает

1. Драйвер [WinDivert](https://reqrypt.org/windivert.html) перехватывает входящие TCP/UDP-пакеты.
2. По локальному порту пакета определяется процесс-владелец (события WinDivert + опрос таблицы сокетов), процессы с одним именем exe объединяются в «приложение».
3. Пакеты ограниченных приложений проходят через token bucket: лишнее ждёт в короткой очереди (≈250 мс), при переполнении пакеты отбрасываются, и TCP сам снижает скорость. Остальной трафик возвращается в стек сразу.

## Сборка и запуск

```powershell
cargo build --release
powershell -ExecutionPolicy Bypass -File .\get-windivert.ps1   # скачает WinDivert.dll и WinDivert64.sys в target\release
.\target\release\speed-limiter.exe                             # попросит права администратора
```

`WinDivert.dll` и `WinDivert64.sys` должны лежать рядом с `speed-limiter.exe`.

## Использование

- Главный переключатель сверху включает и выключает перехват трафика. Когда он выключен, на сеть программа не влияет вообще.
- В списке у каждого приложения: поле со значением лимита, единицы (КБ/с, МБ/с, Мбит/с) и переключатель. Полоска под названием показывает, какую долю лимита приложение сейчас использует.
- «Все процессы» показывает и те, у которых сейчас нет соединений. «По скорости» переключает сортировку (приложения с активным лимитом всегда сверху).
- Настройки хранятся в `%APPDATA%\SpeedLimiter\config.json`.

## Ограничения

- Лимитируется только входящий трафик, исходящий (отдача) не трогается.
- Трафик через VPN/прокси, которые сами принимают данные в своём процессе, учитывается на этом процессе.
- Перехват идёт в пользовательском пространстве, на очень быстрых каналах (гигабит и выше) возможна заметная загрузка процессора. Если лимитов нет, выключите главный переключатель.
- Если программу убить принудительно, Windows закроет дескрипторы WinDivert, и трафик пойдёт как обычно.

## Разработка

```
cargo test        # шейпер, разбор пакетов, конфиг, форматирование
```

Тест `engine::mock_tests` на Linux подставляет вместо WinDivert заглушку на C и проверяет весь конвейер (приём → шейпинг → отправка) на реальных потоках. Для него нужен `cc`.

Структура: `shaper.rs` (token bucket), `packet.rs` (разбор IP), `model.rs` (приложения, порты, процессы), `engine.rs` (WinDivert), `config.rs`, `theme.rs` и `app.rs` (интерфейс).
